# AR Demo (8thWall Studio)

WebAR experience built on the business card. You scan the card, three platforms appear on it, and tapping a platform's disc reveals a 3D model and a label. Each platform stands for one of the three offers on the website (ocre / cyan / violet).

- **Live URL:** <https://ori-co.github.io/ardemo/>. The page is deliberately not linked from the website.
- **Reference test device:** Samsung Galaxy A06.
- **Roadmap and open bugs:** [TODO.md](TODO.md).

## Stack

- **8thWall Studio** (desktop app) to edit the scene. It reads and writes this folder directly.
- **`@8thwall/ecs`** runtime (entity-component system) and **`@8thwall/engine-binary`** (XR engine: SLAM, image targets).
- **webpack 5** + TypeScript for the build, using the scaffolding generated by Studio in `config/`.
- 3D models made in **Blender** and exported as GLB.

## Project layout

```
ardemo-studio/
├── src/
│   ├── .expanse.json     # The scene: entities, transforms, components. Written by Studio.
│   ├── app.js            # XR8 config: list of image targets to load
│   ├── disc-reveal.ts    # Custom ECS component
│   ├── index.html        # HTML shell (loads runtime.js + xr.js, then bundle.js)
│   └── assets/           # GLB models used by the scene
├── image-targets/        # Image target files generated by Studio (.json + 4 images each)
├── config/               # 8thWall webpack scaffolding (normally leave alone)
├── dist/                 # Build output (git-ignored)
├── TODO.md
└── package.json
```

How the build is wired (`config/`):

- `entry-plugin.js` generates a virtual entry that **imports every `.ts` / `.js` file in `src/`** (except `src/assets/`), then calls `ecs.application.init()` with `.expanse.json`. A new component file only has to exist in `src/` to be bundled.
- `@8thwall/ecs` is declared as an external mapped to `window.ecs`, which `runtime.js` defines. Just `import * as ecs from '@8thwall/ecs'` as usual.
- Files in `src/assets/` are imported as **path strings** (`asset-loader.js`) and copied to `dist/assets/`.
- The runtime and XR engine are copied from `node_modules` to `dist/external/{runtime,xr}/`.

## Scene

Snapshot of `src/.expanse.json`. Studio is the source of truth, so check it there if in doubt:

```
Default Space
├── Ambient Light
├── Directional Light          (disabled)
├── Camera                     phone: AR · world tracking
├── Cible d'image              Image Target entity
│   ├── Trigger (1)            cylinder "disc" + disc-reveal
│   │   ├── ARScene_plateform_ocre.glb
│   │   └── Label              "Atelier Vision & Acculturation"
│   ├── Trigger (2)            cylinder + disc-reveal
│   │   ├── ARScene_plateform_cyan.glb
│   │   └── Label              "Prototypage & Developpement"
│   └── Trigger (3)            cylinder + disc-reveal
│       ├── ARScene_plateform_violet.glb
│       └── Label              "Direction de Projet Innovation"
└── Version#                   on-screen UI text, e.g. "V1.6 - Cropped Image Target"

Prefab (outside the space): Plateformes
```

**`Version#`** is an overlay shown on the device, so you can tell which build is actually running on the phone (think GitHub Pages / browser cache). **Update its text with every deploy.** Convention: `V<major>.<minor> - <what changed>`.

## Custom components

### `disc-reveal` (`src/disc-reveal.ts`)

Attached to each `Trigger` cylinder.

1. `add`: hides all the entity's children (platform GLB + label).
2. On `SCREEN_TOUCH_START` on this entity (a tap on the disc), shows them again.

To create a new component, copy this file and keep the same pattern:

```ts
import * as ecs from '@8thwall/ecs'

ecs.registerComponent({
  name: 'my-component',            // name referenced by the scene in .expanse.json
  add: (world, component) => {     // arrow function (see gotchas)
    const eid = component.eid
    world.events.addListener(eid, ecs.input.SCREEN_TOUCH_START, () => {
      // …
    })
  },
})
```

Then attach it to an entity in Studio.

## Image targets

1. Upload the image in Studio. It generates `image-targets/<Name>.json` plus `_original`, `_cropped`, `_luminance` and `_thumbnail` images.
2. Register the JSON in `src/app.js`:
   ```js
   XR8.XrController.configure({
     imageTargetData: [require('../image-targets/<Name>.json')],
   })
   ```
3. On the Image Target entity (`Cible d'image`), select the same target. **The target name in the scene must match the `name` field of the JSON.** Otherwise nothing is tracked, and no error is shown.
4. Remove old targets from both `app.js` and `image-targets/`. Every target listed in `app.js` must exist on disk, or the build fails on the `require`.

## Build & deploy

The site is served from `../ardemo/`, a plain copy of `dist/`. **Never edit `ardemo/` by hand.**

From `ardemo-studio/` (webpack resolves paths from the current directory):

```powershell
npm install                          # once
Remove-Item -Recurse -Force dist -ErrorAction SilentlyContinue   # recommended: the build does not clean dist/
npm run build                        # → dist/
Remove-Item -Recurse -Force ..\ardemo\*
Copy-Item -Recurse dist\* ..\ardemo\
```

Studio can also produce the build. Either way, what you commit in `ardemo/` must be the contents of `dist/`.

Then:

1. Update the `Version#` text (ideally before the build).
2. Commit `ardemo-studio/` **and** `ardemo/` together, then push to `main`. GitHub Pages publishes it.
3. Open <https://ori-co.github.io/ardemo/> on the real device and check the version number on screen.

Why clean before copying: old image targets and assets would otherwise pile up in `dist/` and `ardemo/`, and get deployed for nothing.

### Local testing

- Studio's preview is enough for scene layout and interactions (e.g. `disc-reveal` was validated there).
- `npm run serve` starts webpack-dev-server in development mode.
- Mobile browsers only grant camera access on a secure context (HTTPS), so tracking is best tested on the device via the deployed URL.

## ECS gotchas

Lessons learned the hard way:

| Topic | What to do |
|---|---|
| Component syntax | Studio expects the arrow function form `add: (world, component) => {}`, not the method shorthand `add(world, component) {}` |
| Tap on an entity | Listen on the entity itself: `world.events.addListener(eid, ecs.input.SCREEN_TOUCH_START, cb)`. Listening on `world.events.globalId` and comparing target/eid proved unreliable |
| Event payload | Events are wrapped: use `e.data.target`, not `e.target` |
| Show / hide | Use `world.getEntity(eid).show()` / `.hide()`. `ecs.Hidden.remove` doesn't bring back an entity hidden in Studio |
| `LandingPage is not defined` | Remove `XR8.addCameraPipelineModule(LandingPage.pipelineModule())` from `app.js` |
| Brightness flickering on the platforms | Open bug, see [TODO.md](TODO.md). The directional light is currently disabled |
